Lumen Proxy направляет сайты через ваш прокси по вашим правилам. Свой список доменов с поиском, подключение PAC-скриптов и гарантия, что при недоступном прокси ничего тихо не уйдёт в прямое соединение.

РЕЖИМЫ
• Выключен: расширение не вмешивается, работают настройки Chrome и системы.
• По правилам: через прокси идут сайты из вашего списка и те, что выбрал PAC-скрипт, остальные — напрямую.
• Весь трафик: всё через прокси, кроме исключений и локальных адресов.

СПИСКИ САЙТОВ
• Два списка: «Через прокси» и «Напрямую». Домен действует вместе с поддоменами: example.com охватывает www.example.com.
• Если правила пересекаются, побеждает более точное. Например, google.com идёт через прокси, а mail.google.com — напрямую.
• Мгновенный поиск с подсветкой, даже по десяткам тысяч доменов.
• Вставьте в поиск адрес сайта — расширение покажет, какое правило его покрывает.
• Можно выделить несколько доменов и удалить их или перенести в другой список. Удаление отменяется.
• Добавлять можно сразу пачкой: через запятую, построчно, ссылками. Есть импорт и экспорт в .txt.

PAC-СКРИПТЫ
• Подключаются по ссылке (с автообновлением) или вставкой текста.
• «Направлять в свой прокси»: сайты, которые PAC отправляет в прокси, пойдут через ваш сервер, а не через серверы из скрипта.
• Ваши списки всегда важнее PAC.

ПОПАП
• Показывает, куда пойдёт открытый сайт и по какому правилу.
• Сайт можно добавить в список или убрать из него в один клик, выбрав уровень домена.
• Здесь же переключаются режим и активный прокси.

ЕЩЁ
• Несколько прокси-серверов: HTTP, HTTPS, SOCKS4, SOCKS5, с логином и паролем. Строку вида socks5://user:pass@host:port можно вставить целиком.
• «Проверка адреса» показывает, куда пойдёт любой адрес с текущими настройками.
• Резервная копия настроек в файл. Пароли попадают туда только по отдельной галочке.
• Светлая и тёмная тема берутся из настроек браузера. Интерфейс на русском и английском.

БЕЗОПАСНОСТЬ
• Запрет DIRECT (включён по умолчанию): если прокси недоступен, сайт не откроется — расширение не перейдёт тихо на прямое соединение. Из ответов PAC вида «PROXY …; DIRECT» вариант DIRECT убирается. Если сломается сам PAC-скрипт, Chrome заблокирует запросы, а не пустит их напрямую.
• Изоляция PAC: внешний скрипт не может обойти ваши списки или подменить логику расширения.
• Проверка перед применением: новая версия PAC сначала выполняется в песочнице без доступа к сети. Если в ней ошибка, остаётся прежняя версия. Если Chrome всё же не сможет её выполнить, расширение откатится на предыдущую.
• Загрузка PAC только по HTTPS (HTTP — по явному разрешению), без cookies, до 32 МБ.
• Защита от утечек WebRTC на выбор: не менять, скрыть локальные адреса или только через прокси.
• Без DNS-утечек: локальные адреса определяются по самому адресу, без DNS-запросов.

ПРИВАТНОСТЬ И РАЗРЕШЕНИЯ
• Доступ к сайтам запрашивается только когда нужен: к одному сайту — при загрузке PAC, ко всем — только если у прокси есть логин (иначе Chrome не даст передать пароль).
• Пароли хранятся только локально и не синхронизируются. Пароль получает только тот прокси, для которого он сохранён.
• Без сбора данных. Расширение ничего никуда не отправляет.
